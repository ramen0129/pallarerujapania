# **『パラレル・ジャパニア：クロニクル』スプレッドシート駆動型リファクタリング計画**

本計画は、巨大化したGASコード（コード.gs）からシナリオマスターデータを分離し、スプレッドシートをコンテンツデータベース（CMS）として機能させる「データ駆動型アーキテクチャ」への移行手順、およびコードの記述量と書き込み方針を定義するものです。

## **1\. 役割分担と書き込み方針の概要**

| 対象ファイル / 領域 | 何を書き込むか (What) | どのように書き込むか (How) | どのくらい (Size) |
| :---- | :---- | :---- | :---- |
| **1\. バックエンド (コード.gs)** | ・Web Apps API (doGet, doPost) ・排他制御付きセーブ・ロード (saveProgress, loadStudentProgress) ・シート自動生成・初期化 (getOrCreateSheet) ・スプレッドシートからのシナリオJSON取得 (getMasterScenario) | シナリオのハードコードを100%廃止。初回起動時に「シナリオマスター」シートがなければ自動生成し、セルからJSONを安全にパースしてクライアントへ配信する。 | **約 180 〜 200 行** |
| **2\. スプレッドシート (コンテナバインド)** | ・「プレイ記録」シート（生徒のセーブデータ） ・「シナリオマスター」シート（ゲームの全ノード・TIPS・結末データ） | ・シート名: シナリオマスター ・セル A1: MASTER\_JSON ・セル A2: 全シナリオ構造を圧縮・整形した巨大なJSON文字列を格納。 | **1セルに全シナリオデータ** |
| **3\. フロントエンド (index.html)** | ・単一ファイル原則（Single-File Mandate）に準拠したHTML骨組みとTailwind CSS ・Web Audio API 音響合成 ・モジュール化された因果エンジン (GameEngine, UIController, TimelineState) ・TIPS逆照射モデル ＆ Canvas表彰状PDF | 散乱していたコードを責務ごとに5大モジュールへ完全に分離・整理し、スパゲッティ状態を解消。スプレッドシートとの非同期通信失敗時には内蔵フォールバックデータで即座に起動。 | **約 850 〜 950 行** |

## **2\. モジュール別 詳細書き込みプラン**

### **【Phase 1】バックエンド: Google Apps Script (コード.gs)**

* **ファイルパス:** コード.gs  
* **コード規模:** 約180行（マスターデータ全削除によるスリム化）  
* **主要関数:**  
  1. doGet(e): index.html の出力を返す。  
  2. doPost(e): 非同期セーブのリクエストを安全に処理。  
  3. getOrCreateSheet(): 「プレイ記録」および「シナリオマスター」シートの存在確認と初期構築（JSONの自動書き込み含む）。  
  4. getMasterScenario(): **【核心】** 「シナリオマスター」シートの A2 セルからJSON文字列を読み込み、JSON.parse() して返す。シートが空・未作成の場合はデフォルトのJSONを書き込んで返す。  
  5. registerStudent(katakanaName): 4桁パスコードの自動発行と初期行追加。  
  6. loadStudentProgress(name, pass): 登録名とパスコードの照合・復元。  
  7. saveProgress(data): LockService（30秒排他制御）下での非破壊セーブ。

### **【Phase 2】データベース: スプレッドシート構成**

* **シート①: プレイ記録**  
  * カラム構成: 最終更新日時、名前、パスコード、現在主人公、現在地、達成度、復帰キー、獲得フラグJSON、通過ノードJSON、解放結末JSON、スロット状態JSON（計11列）。  
* **シート②: シナリオマスター（新規追加）**  
  * A1: MASTER\_JSON  
  * A2: MASTER\_DATABASE 全体のJSON文字列。  
  * *メリット:* 現場の先生や開発者がコードを一切触らず、スプレッドシート上のテキストを書き換えるだけでセリフや選択肢の微調整（CMS運用）が可能になる。

### **【Phase 3】フロントエンド: 単一HTML (index.html)**

* **ファイルパス:** index.html  
* **コード規模:** 約900行（モジュール分割による高い保守性）  
* **内部構造:**  
  * \<head\>: Tailwind CSS CDN、jsPDF CDN、カスタムCSSアニメーション（.para-in, .blink-indicator, .scanner-beam 等）。  
  * \<body\>: スタート画面、ノベル表示画面、KEEP OUT画面、BAD END画面、TRUE SECRET END（4幕構成）画面、各種モーダル（図鑑、表彰状PDF、TIPS、パスコード）。  
  * \<script\>:  
    * MASTER\_DB\_FALLBACK: サーバー通信不能時のためのスタンドアロン用マスターデータ。  
    * AudioEngine: Web Audio API による効果音・チャイム・警告音のリアルタイム合成。  
    * TimelineState: localStorage と GAS サーバーのハイブリッド永続化、スロット排他管理。  
    * GameEngine: ノード遷移、トリプル・シンクロゲート評価、即死トラップ判定、真エンド4幕シーケンサー。  
    * UIController: 画面切り替え、ヘッダータブ同期、時間軸図鑑の動的描画。  
    * CertRenderer: Canvas を用いたA4横向き表彰状（通常クリア用ブルー、真エンド用ゴールド第97条刻印）の動的描画とjsPDF出力。

## **3\. 移行・実装の実行順序**

1. **ステップ1:** スプレッドシート側に「シナリオマスター」シートを自動生成し、全シナリオJSONを格納するロジックを組み込んだ コード.gs を作成する。  
2. **ステップ2:** モジュール責務が明確に整理され、スパゲッティコードが解消された index.html を作成する。  
3. **ステップ3:** 結合テスト（抜け駆け阻止テスト、全6結末回収テスト、A4 PDF出力テスト）を実施し、10点満点の完璧な動作を確認する。
