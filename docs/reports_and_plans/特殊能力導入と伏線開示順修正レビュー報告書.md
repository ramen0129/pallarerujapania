## 1. 今回実施した修正の要約

### 1.1 特殊能力の10時台エピソード化
キャラクター完全設計仕様書に定義済みの `special_ability` を、後付け感のない「10時台の危機回避」として本編に実装した。

| 主人公 | 能力 | 実装箇所 |
|---|---|---|
| レン | 足裏・内耳の振動感知（未来予知ではない） | [scenario_ren.html](scenario_ren.html) `A_1045_WATERGATE`：排水管に潜る直前、水圧の脈動増大を感じて退避。直後に濁流が噴出し、能力の正しさが裏付けられる。 |
| エレナ | 一度見た形状を保持する視覚記憶 | [scenario_elena.html](scenario_elena.html) `B_1015_CHECK_REN`：監視モニターの映像と実際の飾り棚の傷の左右差から録画ループを見破り、巡回兵を回避。 |
| ダニエル | 雑音下でも聞き分ける鋭敏な聴覚 | [scenario_daniel.html](scenario_daniel.html) `C_1045`：怒号とサイレンの中から少年の喘鳴を聞き取り、落下事故の直前に救出。 |

### 1.2 ペンダント伏線の開示順修正（DIR_09準拠）
- 当初、[scenario_elena.html](scenario_elena.html) の10:00でマーサがペンダントを見せる直接描写を追加したが、「10時台から匂わせすぎ」との指摘を受けて削除。
- 最終形として、ペンダントの伏線は **11:15のエレナの回想のみ** に一本化。青い火花をきっかけに、マーサが夜ごと握っていた真鍮ペンダントの意匠（百合の紋章・碧の石細工・縁の打痕）を思い出す構成とした。
- [scenario_climax_elena.html](scenario_climax_elena.html) の12:05での照合も、この11:15の記憶を根拠にするよう文言を修正。

### 1.3 「トロッコ問題」としての因果設計
- エレナがレンのペンダントに気づくのは、**レンが12:05に「恐怖を抑えるためペンダントを握る」選択をした場合のみ**（`FLAG_REN_CALM`）。
- 威嚇ルート（`REN_THREATEN`）では、レンの姿勢・行動によりペンダントが観察されず、エレナは血縁の手がかりを得られない。
- この「行動が相手の認識を変える」設計により、単純なフラグ分岐ではなく、レンの選択が協力可能性そのものを生む因果になっている。
- ペンダントを握る仕草を後出しにしないため、[scenario_ren.html](scenario_ren.html) の **10:30**（水門へ急ぐ選択）と **11:05**（センサー監視の選択）にも、同じ「冷静さを取り戻すためにペンダントを握る」行動を追加。12:05の仕草が初出ではなく、レンの一貫した癖として成立させた。

### 1.4 用語・時系列の整合修正
- 「マーサの形見」という表現を削除。マーサは10:00時点で生存し合鍵を渡しているため、「マーサが胸元で握っていたペンダント」に修正（[scenario_climax_elena.html](scenario_climax_elena.html)）。
- ダニエルが12:05に聴取するエレナの独り言を、エレナが実際に選択する台詞（「……逃げてたまるもんですか……絶対に押すのよ」／「……スラムの暴徒なんて信じられない……」）と完全に一致させ、読心ではなく聴覚のみで判断している設定を担保（[scenario_climax_daniel.html](scenario_climax_daniel.html)）。
- レンの水門選択肢を「強行突破」から「濁流の波間を読んで隙間へ潜る」に変更し、能力で察知した危険を自ら無視する矛盾を解消（[scenario_ren.html](scenario_ren.html) `A_1045_WATERGATE`）。
- エレナ・ダニエル視点の12:00本文で、ペンダントの意匠（百合・碧の石細工）を先出ししていた記述を「首元で何かが揺れた」程度に抑制し、12:05の「握る」動作で初めて意匠が明瞭になるよう統一（[scenario_climax_elena.html](scenario_climax_elena.html)、[scenario_climax_daniel.html](scenario_climax_daniel.html)）。

### 1.5 設定資料への反映
[パラレル・ジャパニア_キャラクター完全設計仕様書.md](パラレル・ジャパニア_キャラクター完全設計仕様書.md) の各 `special_ability` に、10時台の初出と12時台の再利用を明記。[パラレル・ジャパニア_シナリオ詳細リファクタリング設計仕様書.md](パラレル・ジャパニア_シナリオ詳細リファクタリング設計仕様書.md) にも該当ノードの改訂内容を追記し、旧設定（「青い布」、対面直後の血縁断定）を除去した。

### 1.6 検証
`node simulate_all_paths.js`（124ノード、破損リンク0、BAD END 23件・クリアEND 2件・DIR_01/02/03/08静的検査すべて通過）および `node build_preview.js`（[local_preview.html](local_preview.html) 再生成）を、各修正のたびに実行し全て成功を確認した。

### 2.2 P0（最優先）指摘事項

1. **JUMP後に未来の選択フラグが残留する**
   [js_state.html](js_state.html) `rollbackFutureSlots()` は同一主人公の未来 `slots` のみを削除し、`FLAG_REN_PRESSED` 等の `userFlags` は残留する。過去へJUMPして選択をやり直しても、古いフラグが動的判定に混入する恐れがある。
   → 恒久進行（既読・収集品・解放済みBAD END）と、時系列に依存する因果フラグを分離し、JUMP時に後者を再構築する必要がある。

2. **クライマックス固有BADが無関係な番号付きBADカードへ接続される**
   [scenario_climax_elena.html](scenario_climax_elena.html) `BAD_ELENA_RETREAT` → `BAD_11`（本来は10:00のレンの虚偽放送に関するカード）、[scenario_climax_daniel.html](scenario_climax_daniel.html) `BAD_DANIEL_RETREAT` → `BAD_12`（本来はエレナの送電遮断のカード）のように、絶望の本文と提示されるBADカードの内容・JUMP先が一致していない。

3. **12:15の遺物スキャン前にTIPSから条文・判例へ到達できる**
   各シナリオ冒頭からTIPSリンクが機能し、`CLIMAX_SCAN` 完了フラグによる開示制御がない。DIR_03が定める「12:15まで条文を秘匿し、ディストピアとして描く」という叙述トリックが、TIPS経由で無効化される。

### 2.3 P1（高優先）指摘事項

- 水門・センサー・監視コンソール等、多くの二択が別キャラクターのフラグのみで結果が決まり、プレイヤー自身の選択が結果を左右しない「疑似選択」になっている。
- 3視点別クライマックス（`CLIMAX_REN/ELENA/DANIEL_DECISION`）で各々「同時押し」を完了した後、[scenario_climax.html](scenario_climax.html) `CLIMAX_DECISION` で再度同じ同時押しを要求しており、能力・信頼構築の到達点が二重化している。
- BAD ENDの `hint` が「何時の誰の選択肢を選べ」と直接的すぎ、DIR_11が求める「推理を促す問いかけ」になっていない。

### 2.4 P2（中優先）指摘事項

- ダニエル・エレナの台詞に公民科的な完成された定義の朗唱が多く、緊急場面の緊張感より説明が先行する箇所がある。
- オーガスト卿の資源不足という問いに対し、選択肢が「抵抗＝正解／躊躇＝BAD」に偏りやすく、公共の福祉の比較衡量をプレイヤーに委ねきれていない。
- [js_tips.html](js_tips.html) の朝日訴訟解説は、上告審が原告死亡により訴訟終了となった経緯や学説対立の整理が不足している。
- [scenario_shin.html](scenario_shin.html) でシンが「いつかレンが笑っている姿がはっきり見えた」と語る箇所は、DIR_08（認知境界）に抵触しうるため、「そう祈った」という願望表現への修正が望ましい。

## 3. 次のアクション候補（優先順）

1. `js_state.html` のJUMP状態ロールバックを、恒久進行／時系列因果フラグに分離して再設計する。
2. クライマックス専用BAD END（`BAD_ELENA_RETREAT` 等）に、内容と一致する専用カード・JUMP先を割り当てる。
3. `CLIMAX_SCAN` 完了フラグをTIPS表示条件に組み込み、12:15以前は条文・判例の閲覧をロックする。
4. 水門・センサー等の二択に、プレイヤー操作キャラクター自身の選択で変化する情報・代償・到達速度の差を持たせる。
5. 3視点別クライマックスの同時押しと、合流後の最終同時押しを一本化し、各能力を最終同期の役割分担として統合する。
