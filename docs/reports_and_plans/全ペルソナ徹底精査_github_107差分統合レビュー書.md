### 3.3 プログラマーが摘発した3大構造的脆弱性（解体すべき時限爆弾）

#### 💣 脆弱性 1【P0最重要】：`rebuildFlags()` による未来フラグのゾンビ化現象
- **該当箇所**: [js_state.html](file:///c:/Users/佐々木篤史/Desktop/pallarerujapania/github_107/js_state.html#L22-L35)
- **問題のコード**:
  ```javascript
  function rollbackFutureSlots(targetNodeId) {
    // ... 未来の state.slots[slotKey] を正しく delete している ...
    rebuildFlags();
  }

  function rebuildFlags() {
    var flags = new Set();
    Object.keys(state.slots).forEach(function(k) {
      var val = state.slots[k];
      if (typeof val === "string") flags.add(val);
      else if (val === true) flags.add(k);
    });
    // ★重大なバグ：過去に userFlags に入った全要素を、無条件で戻してしまう！
    state.userFlags.forEach(function(f) { flags.add(f); });
    state.userFlags = Array.from(flags);
  }
  ```
- **なぜこれが致命的か**:
  - 428型アドベンチャーでは、**「過去に戻って選択を変えたら、未来の因果は消滅しなければならない」**。
  - しかし上記の実装では、一度 `state.userFlags` に記録されたフラグ（例：`A_SYNC_SCREENS` や `B_NET_CUT`）は、どれだけ過去にJUMPしてスロットを巻き戻しても、**`state.userFlags` 自身を参照して全フラグを再注入するため、絶対に消去されない**。
  - これにより、例えば「放送室でマイクを掴む」を選び直したのに、以前選んだ「画面を強制同期する」フラグも同時に立ちっぱなしになり、動的パラグラフ判定が二重発火・矛盾する。
- **完全修正パッチ（処方箋）**:
  `userFlags` を「時系列因果フラグ（`slots` から純粋算出）」と「恒久セーブフラグ（アワー突破、収集実績、真エンド到達）」に厳格に分離する。
  ```javascript
  function rebuildFlags() {
    var flags = new Set();
    // 1. スロット（現在の因果）から純粋にフラグを導出
    Object.keys(state.slots).forEach(function(k) {
      var val = state.slots[k];
      if (typeof val === "string") flags.add(val);
      else if (val === true) flags.add(k);
    });
    // 2. 恒久実績（JUMPでも消してはならないもの）のみをマージ
    var PERSISTENT_PREFIXES = ["A_HOUR", "B_HOUR", "C_HOUR", "PIECE_", "TRUE_"];
    state.userFlags.forEach(function(f) {
      if (PERSISTENT_PREFIXES.some(function(pre) { return f.indexOf(pre) === 0; })) {
        flags.add(f);
      }
    });
    state.userFlags = Array.from(flags);
  }
  ```
